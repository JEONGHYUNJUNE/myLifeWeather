# 운동 기록

- `/fitness`: 항상 사용자 선택 화면. 마지막 사용자로 자동 이동하지 않는다.
- `/fitness/hyunjun`, `/fitness/yujin`: URL로 사용자를 확정한 개인 대시보드. 상단 ‘사용자 변경’으로 선택 화면에 돌아간다. 그 외 사용자 URL은 404.
- 기존 Next.js App Router / React 상태 훅 / CSS / lucide-react 유지. 추가 의존성 없음.
- 프로그램: `data/fitness.ts`, 순수 계산: `model.ts`, 저장 어댑터: `storage.ts`, 컨트롤러: `useFitnessController.ts`.

## 진행률

기간은 2026-10-01부터 2027-01-15까지. 첫 주와 마지막 부분 주를 포함한 달력 주차는 16주다. **전체 목표는 주차 수와 무관하게 인당 30회**다.

`progress = Math.min(실제 누적 완료 횟수 / 30 * 100, 100)`

선택 운동을 포함한 모든 완료 운동이 누적된다. 예: 1주차 1회 + 2주차 1회 + 3주차 4회 = 6회, 진행률 20%. 지난 주 부족분을 다음 주 운동으로 따라잡을 수 있다. 주간 완료 여부는 별도 값이다. 현준 A+B, 유진 합계 2회가 주간 기본 목표다.

캐릭터 위치는 현재 날짜, 성장 단계는 개인 누적 진행률의 0/25/50/75/100% 구간이다. 전체 진행 바와 수치 변화 애니메이션, 단계별 소품 전환에 반영하며 reduced-motion에서는 애니메이션을 제거한다. 신체 목표 달성과 기록 달성률은 별개다.

## 사용자별 저장

- 현준: `life-weather-fitness-hyunjun-v1`
- 유진: `life-weather-fitness-yujin-v1`

각 키에는 해당 사용자 기록만 저장한다:

```json
{
  "version": 1,
  "records": {
    "2026-10-01": {
      "running-1": {
        "date": "2026-10-03",
        "completed": true,
        "sets": {},
        "minutes": 25,
        "distance": 2.5
      }
    }
  }
}
```

기존 통합 키 `life-weather-fitness-v1`은 개인 키가 없을 때만 읽고 해당 사용자의 기록만 옮긴다. 기존 데이터는 삭제하지 않는다. 마지막 선택 사용자와 관계없이 URL의 사용자만 불러오고 저장한다. 서로 다른 사용자 대시보드를 두 탭에서 열어도 상대 기록을 덮어쓰지 않는다. 기존 JSON이 손상된 경우 덮어쓰지 않고 안내와 함께 임시 모드로 연다.

웨이트 완료는 세트에서 자동 파생한다. 처음 두 주는 2세트, 이후는 프로그램의 정상 세트 수다. 모든 완료에는 해당 주 내 날짜가 필요하며 러닝 시간/거리는 선택이다.
